# 1. Phase-9 verdict

**PASS WITH TARGETED PHASE-10 RISKS; no earlier phase must be reopened now.**

The full product can be walked coherently from first boot through D40, mastery/remix play, persistence failures and all required input modes without inventing a missing core rule. The executable-map fantasy remains central throughout.

The simulation did identify important risks, but they are adversarial validation targets rather than current contradictions:
1. late-game causal ribbons can become too broad even when the underlying causal graph is deterministic;
2. linked-map layer switching can become working-memory tax if more than one remote consequence matters at once;
3. Stability can become passive verification if overused;
4. mastery can become checkbox cleanup if authored thresholds merely ask for fewer final differences;
5. D13–D22 is the largest repetition danger because all six primitives are known but linked maps have not arrived;
6. controller/keyboard logical focus needs strong spatial predictability on dense border/water candidates;
7. semantic relabeling is powerful enough to become a recurring shortcut unless content validation attacks it;
8. deterministic recovery/cloud rules are coherent, but implementation must make conflict choice understandable without exposing save-schema jargon.

No risk above requires changing the product thesis or canonical semantics before Phase 10.

# 2. First boot -> Department Desk -> D01

## 2.1 First boot

Player launches the game. No cinematic blocks control. First-launch accessibility setup appears with sensible defaults and immediate preview for UI scale, reduced motion, flash reduction and input glyph family. The setup can be accepted quickly without implying that accessibility is an advanced settings task.

After setup, title screen appears. With no prior profile, `Continue` is absent/disabled clearly and `Department Desk` is primary.

The Desk contains one available file, D01, and future folders visually exist without dumping forty locked cards into a progression wall. No currencies, stars-as-keys or shop affordances appear.

**Fantasy check:** PASS. Bureaucratic framing supports the map authority fantasy without delaying the first map edit.

## 2.2 D01 first 5 minutes

0:00–0:30 — brief states a concrete civic need in one sentence. Map and miniature world are both visible. A courier is blocked by a missing road connection. The matching candidate edge is visually corresponded, not explained through a modal lecture.

0:30–1:15 — player selects the only available road tool and commits the snapped legal segment. The map changes first; the world road appears as its causal twin; courier route rebuilds and courier advances on the bounded reaction beat.

1:15–2:00 — causal ribbon reads approximately `Road added -> route connected -> courier can reach destination`. Player can select the courier and see its intended route.

2:00–3:10 — second micro-problem asks the player to remove/change a road so another route changes. The game no longer highlights the exact answer; it teaches transfer.

3:10–4:20 — a harmless wrong but structurally legal edit is allowed to commit. Requirement becomes broken/currently unsatisfied, causal ribbon explains why, Undo restores exact pre-edit state. This is important: D01 teaches the distinction between illegal grammar and bad civic consequence.

4:20–5:00 — player clears the dossier. Completion emphasizes the causal result, not time or Undo count.

**Potential repair:** Phase-6 text described D01 as one road teaching sequence, while older tournament examples sometimes used bridge/border within the first five minutes. Canonical Phase 5/6 wins: D01 is road-only teaching. This is historical drift, not a live contradiction.

# 3. Demo experience — 15–25 minutes

The canonical demo uses early content through approximately D04/D05-scale teaching, not a compressed parade of all mechanics.

Minute 0–5: D01 road causality and Undo.

Minute 5–10: D02 demonstrates that removing/re-routing a road can protect one route while harming another. The player sees two agents interpret the same topology differently enough to understand that world agents matter.

Minute 10–15: D03 introduces bridge/water crossing. Bridge is placed only at a legal crossing slot; the preview shows structural support but does not spoil downstream agents.

Minute 15–20: D04 creates the first collateral consequence: a bridge solves desired connectivity but also enables an unwanted agent/livestock path. Player must use the already learned road relation to solve both.

Minute 20–25 optional/target end: a compact border or restricted-zone preview can provide the promised interpretation difference only if the selected demo dossier is within the Phase-5 teaching order. The safest canonical demo package is D01–D04 plus a purpose-built bounded demo capstone that uses only already introduced primitives and one visible permission distinction. It must not silently teach landmark/waterway/linked systems early.

**Finding P9-D1 — demo boundary wording needs adversarial check, not rule change.** Phase 6 says demo should include “border or restricted-zone interpretation difference,” while Phase 5 places border at D05–D06 and restricted zone D07–D08. A 15–25 minute demo can include a curated early subset, but content order must not be violated accidentally. Phase 10 must decide whether demo contains D01–D05, a shortened canonical D05, or a demo-only capstone using taught tags. The underlying mechanics are specified; this is packaging/pacing, not a mechanical contradiction.

Demo end card promises later semantic names, waterways, Stability and linked maps as escalation. Save/progress import contract is available if the full game is installed later.

**Demo hook check:** PASS if the first collateral bridge consequence lands by ~15 minutes. If it lands later than 20 minutes in playtest, demo pacing fails the Product Thesis gate.

# 4. First 30–60 minutes — Act I

D05 introduces border ownership. Crucially, the player sees that the border is not a physical wall: the road remains, but a gate/resident/patrol interpretation changes because jurisdiction changes. This is the first major proof that ordinary map notation is executable semantics, not merely geometry.

D06 combines route and ownership. The obvious shortest route can become unusable for a jurisdiction-locked agent after a border change. Inspect card explains the permission fact without prescribing an edit.

D07 introduces restricted-zone policy. A zone denies one class but not another; pattern+icon+text make this readable without color dependence.

D08 synthesizes road + bridge + border + zone. It is the first dossier where the player should form a multi-system hypothesis before editing. Optional mastery appears clearly subordinate to baseline clear.

### D08 simulated solution experience
- player notices courier needs crossing;
- obvious bridge also gives livestock garden access;
- restricted zone can block livestock but must not block resident/service path;
- border position changes which gate resident may use;
- player finds a final map with all baseline predicates true;
- if Stability=1, player explicitly starts Verify Stability and sees one deterministic beat;
- completion unlocks first remix pack according to Phase-7 milestone rules.

**Act-I boredom check:** PASS. Each pair introduces a new interpretation dimension quickly enough.

**Learning check:** By D08, player has experienced geometry, crossing, ownership and permission as four different meanings of map authority. This is enough foundation for semantic labels later.

# 5. Act II — competing interpretations, D09–D16

D09 landmark relabeling is deliberately surprising: a physical building does not move, but changing its official semantic label causes a Semantic Seeker/Courier query to resolve differently. Correspondence animation must emphasize `official name -> target registry -> route`, otherwise this can feel magical rather than bureaucratic.

D10 permits duplicate semantic targets under visible deterministic nearest-reachable/stable-ID resolution. Agent Inspect must state the tie-break in plain language. Duplicate stable IDs remain invalid content; duplicate semantic names are not identity duplication.

D11–D12 introduce editable waterway connectivity and its interaction with ferries/bridges. The critical moment is a water edit that invalidates an unsupported bridge as a derived consequence. Causal ribbon must nest that automatic bridge removal under the water edit so it never looks like the game secretly spent a second intervention.

D13–D16 recombine all six primitive families with 2–5 agents and modest Stability.

### Repetition stress test
This is the first danger zone. The player knows the whole tool vocabulary but does not yet have Procession/linked maps as major structural escalation. Four dossiers that merely say “satisfy two checks with a different theme” would flatten the game.

Required authoring diversity, already compatible with Phase 5:
- one dossier centered on semantic ambiguity rather than connectivity;
- one on water/road mutual validity;
- one on permission asymmetry where the physically shortest route is wrong;
- one on route-length/service bound where removing infrastructure is the elegant answer.

No new mechanic is needed. Phase 10 must attack D13–D16 for repeated solution templates.

**Act-II fantasy check:** PASS. Landmark semantics strengthen the core hook rather than dilute it.

# 6. Act III — civic chains, D17–D24

D17–D22 make second-order chains routine. A8 Procession appears as a specialist only after the player understands route, jurisdiction and semantics independently.

A representative D18 chain:
`Border shift -> market ownership changes -> Commercial Carrier permission changes -> service route changes -> protected hospital service predicate breaks.`

The causal ribbon initially shows the shortest material chain. Expanding it reveals siblings. The player should never be shown a raw graph dump by default.

### First complex Stability use
A Procession dossier can require a route predicate to remain valid for 3 cycles while other agents move. Player reaches a green snapshot, explicitly starts Stability, cycle 2 causes a route contention/arrival change, and verification stops on the first broken predicate. The failed verification is one history transaction. Player can Undo to exact pre-verification state or continue from evolved state.

**Risk P9-R1 — passive Stability.** If many dossiers end with 3–5 cycles that simply confirm an already obvious solution, the feature becomes waiting. Authoring rule for Phase-10 attack: Stability >1 must have a plausible temporal reason and at least one meaningful state transition in the known validation path. Speed/reduced animation prevents time waste but does not cure pointless verification.

### D23–D24 linked-map foreshadowing
D23 shows a non-editable inset: local connector projects upward. Player selects source and sees target correspondence. There is no choice between layers yet.

D24 permits one-way local -> regional projection while edits remain local. The key teaching sentence is not lore; it is an ownership stamp: `This connector is authoritative here; Regional Ledger receives it.`

**Layer-comprehension check:** PASS on paper because ownership is introduced before two-layer editing.

# 7. Act IV — linked authority, D25–D32

D25 is the first true two-layer edit case. Exactly one regional fact family is editable. The player can switch between Region and district, but only two surfaces are visible at once.

### D25 simulated remote consequence
1. player edits regional connector;
2. source fact flashes with `authoritative here` stamp;
3. district tab receives consequence badge;
4. causal ribbon records `Regional connector -> District portal availability`;
5. selecting event jumps to the district portal;
6. local agent route rebuilds;
7. objective updates.

No player must remember ownership from tutorial text; the UI can always answer where the fact is owned.

D26–D28 add one or two cross-layer projections. If a tester cannot explain a remote consequence here, the canonical Phase-5 rule already says later layer count must compress rather than escalate.

D29–D32 may use 2–3 layers, but only up to three linked relations relevant to one solution chain.

**Risk P9-R2 — layer hopping.** A valid but boring strategy is to bounce between layers after every edit and inspect every badge. This is not an exploit but can destroy flow. Phase 10 must test whether causal badges and source/target jump reduce this to purposeful navigation. Do not add an omniscient multi-layer forecast, because that would spoil reasoning and overload Deck UI.

**Deck check:** PASS conditionally. Two-surface ceiling and slide-over case rail are sufficient on paper. Four total layers are acceptable only because they are navigated, not shown simultaneously.

# 8. Act V — D33–D40 late-game density

Act V adds no new primitive. Difficulty comes from compact conjunctions across known semantics.

A representative D37–D39 case may contain 3–4 layers but only two visible/editable simultaneously, 6–10 agents, 3–4 completion goals, up to 2 invariants, <=5 reaction beats and <=5 Stability cycles.

### Causal ancestry readability under density
Suppose one regional connector changes, which alters district portal availability, which reroutes a Commercial Carrier, which changes arrival/service state, while a border-owned market remains relevant to a ferry objective.

Default causal ribbon must prioritize the chain attached to the currently broken/selected requirement. Sibling consequences are collapsed. `Next affected object` cycles descendants. This prevents “causal graph as debug console.”

**Risk P9-R3 — breadth explosion.** Even with a small ruleset, one edit can affect many agents. Phase 10 must impose/readability-test a presentation budget: not a new simulation limit, but a requirement that authored late dossiers avoid simultaneous irrelevant descendants that cannot be visually parsed.

### D40 synthesis
D40 is not a bespoke boss. It uses familiar primitives, A1–A10 within roster ceilings, linked authority and visible objectives. A baseline player with zero mastery marks can clear it.

The ideal D40 emotional beat is not “new final mechanic”; it is recognizing a clean, surprisingly small intervention that resolves a dense-looking civic case.

Completion records baseline campaign ending/Department acknowledgement without turning mastery into mandatory postgame.

**Zero-mastery completion check:** PASS. No Phase-7 gate requires mastery currency.

# 9. Post-campaign mastery and remix loop

After D40, the Desk exposes unfinished mastery marks and available remix cases without presenting them as chores required for a “real ending.”

### Meaningful mastery example
Replay D18. Baseline solution used five final map differences. Clean Intervention asks for <=3. Player now understands semantic routing well enough to relabel one landmark and remove one road instead of reconstructing two corridors. This produces a qualitatively more elegant solution.

### Bad mastery example
Replay D18 with exactly the same reasoning but a threshold of four instead of five. That is checkbox cleanup and should fail authoring review.

**Risk P9-R4 — mastery shallowness.** Every mastery contract must force a different insight, cleaner causal compression or stronger stable state, not merely repeat the baseline with one fewer arbitrary difference. This can be enforced in content review without changing mastery families.

Remix cases change bounded initial conditions/objectives on validated substrates. They should feel like “same grammar, surprising sentence,” not randomized chores.

Hour-10 value therefore depends less on raw campaign length and more on whether mastery/remixes expose alternative causal structures. Phase 10 must attack all 12 planned remixes for template reuse.

# 11. Quit/recovery simulations

## 11.1 Quit mid-edit preview
Preview has not committed. No domain mutation exists. Resume returns to last committed checkpoint; presentation may discard the uncommitted preview.

## 11.2 Quit immediately after accepted edit
Edit transaction commits atomically at application/domain level before presentation finishes. Recovery loads the newest valid save generation/checkpoint. The player may see the resolved state without having watched its animation; causal ribbon/event log explains the last transaction.

## 11.3 Quit mid-Stability
Stability verification is a separate transaction. Persistence must not fabricate half-applied beats. Resume uses the last valid checkpoint/verification state defined by the saved transaction boundary. If the exact active verification state is supported, it must carry explicit cycle index; otherwise safe recovery returns to pre-verification checkpoint and tells the player verification was interrupted. Phase 8 allows recovery coordination; implementation must choose one deterministic representation and test it.

**Finding P9-T1:** this is implementation-flexible, not gameplay-ambiguous, because Stability outcome is deterministic and replayable. Phase 10 should verify that the technical spec's checkpoint contract is explicit enough for implementation handoff.

## 11.4 Corrupted primary save
Checksum/version validation fails. Loader tries temp/backup generations in defined order and selects newest valid compatible envelope. Player gets a concise recovery notice. Corruption never causes silent reset to zero if a valid backup exists.

## 11.5 Cloud divergence
Two progress candidates exist. Monotonic baseline clears/tutorial tags/mastery facts merge. Divergent active dossier branches are never merged into a synthetic state. One active branch is selected according to adapter/conflict policy or player choice when available. UI speaks in human terms (`This device has a newer unfinished Dossier 18`) rather than hashes/generations.

**Persistence check:** PASS on paper.

## 12.1 Mouse + keyboard
Player can select every primitive, preview, commit/cancel, inspect map/world correspondence, pan/zoom, Undo/Redo, navigate history, start/pause/step Stability, switch linked layers, use Desk/settings and complete D40 without controller.

No action requires freehand accuracy because road/water/border/zone edits snap to authored candidates and landmark labels use bounded choices.

## 12.2 Keyboard-only
Logical focus enters map pane. Arrow navigation selects nearest legal candidate by cardinal relation. Endpoint tools enter a two-step focus mode. Tab moves to world/case/history/Stability/layer navigation. `Correspondence` frames paired object. Causal descendants are cycleable.

**Risk P9-R5 — dense focus graph unpredictability.** Border candidates on irregular authored graphs can make “nearest cardinal” feel inconsistent. This is a UX implementation risk, not a new gameplay rule.

## 12.3 Controller-only

Linked layer switching cannot steal the same shoulder binding ambiguously while an edit gesture is active; context glyphs must state current function.

**Input completeness:** PASS on paper; Phase 10 should adversarially test contextual-binding ambiguity.

# 13. Hostile/unusual behavior

## 13.1 Brute-force Undo
Player tries every legal single edit, watches requirements, undoes. Early dossiers are intentionally enumerable. Mature dossiers must contain enough multi-step, remote or Stability consequence structure that one-step probing does not outperform causal reasoning. Undo remains free.

**No repair to Undo.** Punishing Undo would damage learning. Phase 10 must attack mature dossiers/branching factor instead.

## 13.2 Edit thrashing
Player alternates one road on/off repeatedly. Each accepted edit is a valid transaction and advances bounded reaction beats. Because agent state changes across edits, toggling topology is not necessarily a no-op. Undo restores exact checkpoints; repeating commands from changed states remains deterministic.

No achievement/mastery is based on raw edit count, so thrashing has no reward exploit.

## 13.3 Layer hopping
Player switches layers continuously without editing. Time does not advance. No state exploit. UX risk only; see P9-R2.

## 13.4 Duplicate semantic names
Allowed only when dossier explicitly permits. Semantic Seeker selects nearest reachable, then stable-ID tie-break. Inspect explains resolution. Stable object IDs never change with names.

No ambiguity remains mechanically.

## 13.5 Intentionally trapped agents
Player redraws zone/border so an agent's current node becomes forbidden. Legal map edit commits. Agent becomes TRAPPED and may leave toward permitted space but not move deeper into forbidden area. Objective/invariant may fail. No teleport.

This is valid experimentation, not corruption.

## 13.6 Repeated restart
Restart restores canonical initial dossier state. It does not erase durable completion/mastery records unless player explicitly chooses a broader progress reset. Repeated restart cannot farm currency because none exists.

## 13.7 Stale command / double input
Presentation sends semantic command with pre-state/session revision/hash contract. First valid commit advances revision. Duplicate/stale command fails idempotently before a second mutation. No double road, double mastery or double reaction window.

## 13.8 Illegal edit spam
Illegal commands do not mutate state or advance beats. Exact reason remains inspectable. This cannot be used to freeze/advance agents selectively.

## 13.9 Pause/animation skip abuse
World time advances only through accepted edits/Stability semantics, never wall-clock animation. Skipping/reducing animation cannot change outcome.

**Hostile-behavior check:** PASS mechanically.

# 14. Hour-10 repetition/content exhaustion audit

The six primitives are intentionally fixed, so the game succeeds only if interpretation depth creates new reasoning rather than cosmetic variation.

### Strong diversity axes already present
- topology vs ownership vs semantics vs permission;
- road agents vs ferry/water agents;
- reachability vs exclusion vs adjacency vs route bound vs sequence;
- immediate consequence vs Stability consequence;
- local layer vs projected authority;
- baseline solution vs elegant mastery;
- agent archetype differences on the same physical map.

### Highest-risk flat zones
1. D13–D16: full vocabulary known, linked maps absent.
2. D17–D22: second-order chains could become “follow causal ribbon until green” if objectives are too similar.
3. D29–D36: linked-map novelty could be overused as mere extra tabs.
4. remixes: bounded parameter changes could feel like recycled campaign states.

### Phase-10 required attack
For every consecutive 3-dossier window, classify the dominant reasoning transformation. Reject/repair windows where the same transformation solves all three, even if themes/agents differ. For remixes, require at least one changed causal dependency or solution insight, not merely moved starts/thresholds.

**Content exhaustion verdict:** not disproven, not solved by specification alone. It is an explicit adversarial/content-validation gate, not a reason to add mechanics.
